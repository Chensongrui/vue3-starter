# 2026-09-10

## 项目架构分析（vue3-starter）

对工程做了一次完整架构梳理（只读，未改动代码）。

**技术栈**：Vue 3.5 + Vite 6 + TypeScript 5.7 + Vue Router 4 + Pinia 2 + Element Plus 2.9 + Axios 1.7 + Sass。

**分层结构**（自上而下）：
1. 启动入口：index.html → src/main.ts（全局注册 Element Plus + 全部图标 + 中文语言包、注册 router、setupStore）
2. 路由布局：src/router/index.ts（导出 `menuRoutes` 供菜单复用）、src/layout/index.vue（侧边栏+顶栏+面包屑+过渡动画）、layout/components/Sidebar.vue
3. 视图层：views/home、about、demo/{table,form,store}、error/404
4. 状态层：Pinia，全部使用 setup 组合式写法，modules/{app,user,counter}，index.ts 统一 `export *`
5. 网络层：api/request.ts（axios 封装 + 请求/响应拦截器，约定 `{code,data,message}`，code 0/200 为成功且自动剥壳返回 data）、api/user.ts
6. 后端：开发期通过 vite proxy `/api` → `VITE_PROXY_TARGET`（默认 http://localhost:8080），并 rewrite 去掉 /api 前缀

**关键设计点**：
- 菜单由路由表驱动：Sidebar 读取 `menuRoutes` 递归 buildMenus，有 `meta.title` 才显示，`meta.hidden` 隐藏，无 title 的容器路由自动展开子级。新增页面只需加路由 + 建 vue 文件。
- 别名 `@` → src，vite.config.ts 与 tsconfig.json 的 paths 双向配置。
- 构建按 manualChunks 拆包：vue 系、element-plus 各成独立 chunk。实测 dist 中 element-plus 约 1.06MB、vue 约 109KB、index.css 约 355KB。
- 路由守卫仅做 document.title 设置，未做登录鉴权。

**发现的待完善点**：
1. 无登录页、无鉴权守卫，user store 的 login 是 mock，token 只写本地存储。
2. Element Plus 全量引入 + 全量图标注册，打包体积偏大，未做按需引入。
3. `meta.icon` 是字符串 + `<component :is>` 动态渲染，依赖图标已全局注册；TS 层面对 meta 字段无类型扩展（未声明 `RouteMeta`）。
4. 无 ESLint/Prettier、无测试。
5. 生产环境 VITE_API_BASE_URL 仍为 `/api`，需部署层配合反向代理。

## 需求实现：登录页 + 路由守卫

按上述问题清单第 1 项落地，演示账号 `admin / 123456`。

**新增文件**
- `src/utils/auth.ts` —— token 统一读写（`getToken` / `setToken` / `removeToken`，键名 `token`，默认 localStorage）。这是唯一直接碰存储的地方，换 sessionStorage 或加过期只改这一个文件。
- `src/views/login/index.vue` —— 登录页。el-form 校验（用户名必填、密码 ≥6 位）、loading 态、回车提交、`@submit.prevent` 防原生提交、成功后按 `route.query.redirect` 回跳。

**改动文件**
- `src/store/modules/user.ts` —— 重写。`login` 改为 async 并返回 token；`userInfo` 类型从 `UserInfo` 改为 `UserInfo | null`（语义更正确：未登录时无用户信息）；新增 `fetchUserInfo`、`nickname`、`roles`、`avatarText` getter；`logout` 清 store 与本地凭证。mock 实现，文件内注释给出替换成真实接口的写法。
- `src/router/index.ts` —— 新增 `/login` 路由（**不放 menuRoutes**，避免出现在左侧菜单）；`WHITE_LIST = ['/login']`；守卫四步：设标题 → 无 token 跳登录页并带 `redirect` → 已登录访问登录页回首页 → 已登录但 userInfo 为空（刷新场景）补拉一次，失败则清 token 跳登录页。
- `src/main.ts` —— **`setupStore(app)` 提到 `app.use(router)` 之前**，保证首次导航时守卫里能拿到 store。
- `src/layout/index.vue` —— 顶栏显示 `userStore.nickname` 与 `avatarText`；下拉菜单加 `command` 绑定，退出登录走 `ElMessageBox.confirm` 二次确认（catch 掉取消的 reject）。
- `src/api/request.ts` —— 改用 `getToken()`；顺带修掉 axios 1.7 类型报错（`service.request(config) as unknown as Promise<T>`）。
- `src/views/demo/store.vue`、`src/views/home/index.vue` —— 适配 userInfo 可空（`userInfo?.xxx`、`userInfo?.roles ?? []`，home 改用 `userStore.nickname`）。
- `src/views/demo/table.vue` —— 修掉 el-table 插槽 `DefaultRow` 与 `UserRow` 不兼容的类型报错，改为调用处 `row as UserRow` 断言。
- `README.md` —— 目录树补 utils/login，新增「### 8. 登录与路由守卫」，示例页表格加登录页，FAQ 加两条（刷新跳回登录页、卡在登录页），「下一步」去掉已完成的登录项。

**验证结果**：`npm run type-check` 与 `npm run build` 均零报错通过（顺带清掉了 2 个原有类型报错）。

**踩坑记录**
- `curl http://localhost:5173` 返回 502 —— 本机环境设置了 `http_proxy/https_proxy`，需 `curl --noproxy '*'` 或改用 `127.0.0.1` 才能访问本地服务。
- Vite 启动加 `--no-open` 可禁止自动打开浏览器（cac 的布尔取反语法）。

## 环境踩坑：agent-browser 在本机跑不通

想用浏览器做登录流程的端到端验证，结论是**本机暂时不可用**，记录一下避免重复踩：

1. **全局安装被禁止**：`npm install -g agent-browser` 违反环境的运行时隔离规则（禁止 `npm install -g`）。
   替代方案：装到托管目录 `C:\Users\Admin\.workbuddy\binaries\node\workspace`，用
   `node_modules/.bin/agent-browser` 调用。**该目录原本不存在，需要先 mkdir。**
2. **插件自带的 setup.sh 在 Windows 上会失败**：它把 Git Bash 路径 `/c/Users/...` 直接传给
   `powershell.exe -File`，PowerShell 不认这个路径。要直接调用
   `templates/install-windows.ps1`。
3. **install-windows.ps1 也会失败**：它用 `$LASTEXITCODE` 判断 npm 结果，但 npm.ps1 包装脚本在
   StrictMode 下未定义该变量，报 `检索不到变量"$LASTEXITCODE"`。绕过办法是直接跑 npm 命令，
   不经过该 ps1。
4. **Chromium 下载正常**：`agent-browser install` 约 43 秒下完 196MB，
   装到 `C:\Users\Admin\.agent-browser\browsers\chrome-153.0.8010.36`。
5. **致命问题**：`agent-browser open <url>` 会**永久挂起**，无任何输出（实测跑了 4 分钟被强杀）。
   已设置 `NO_PROXY=localhost,127.0.0.1`（本机有 `http_proxy=127.0.0.1:61089` 拦截，
   不加会拿到 502），但仍未解决。怀疑是 daemon 启动环节的问题，未进一步定位。

**结论**：登录/守卫功能只做了静态验证（`type-check` + `build` 全绿），浏览器端到端验证未完成。

**另外**：本机 `chrome.exe` 进程全部来自 `C:\Program Files (x86)\Google\Chrome\Application\`，
是用户自己的浏览器，清理残留进程时**不要误杀**。

**PowerShell 工具注意**：本环境下 PowerShell 工具不返回 stdout，需要
`Out-File` 到临时文件再用 Read 读取。
